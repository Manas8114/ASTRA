## 2024-10-14 - Removed Default Fallback Secrets
**Vulnerability:** Default static fallback secrets were used for both the A1 interface (`astra-secret-token`) and RBAC authorization (`admin-secret-token`, `viewer-secret-token`) via `os.getenv` fallbacks.
**Learning:** Default static API tokens in `os.getenv` fallbacks create a severe security risk. If operators fail to explicitly set environment variables in production, the application silently defaults to known, hardcoded credentials, making the system immediately vulnerable to anyone who examines the source code. The issue was exacerbated by using simple equality checks (`if token == ADMIN_TOKEN:`) which, if `ADMIN_TOKEN` became `None` due to a missing fallback, could potentially evaluate to true if the client somehow passed a `None` token payload, highlighting a second failure mode.
**Prevention:** Never use hardcoded fallback values for secrets in `os.getenv` or `config` objects. Always ensure the absence of a secret explicitly fails securely (e.g., `if not expected_key`). Furthermore, when doing equality comparisons for authentication, defensively verify the secret exists before checking equivalence (e.g., `if ADMIN_TOKEN and token == ADMIN_TOKEN:`).
